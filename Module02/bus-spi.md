# Bus Profile: SPI

**Student:** Haocheng Feng · **Module 2, Task 2** · **Assigned bus:** SPI

SPI (Serial Peripheral Interface) is a synchronous serial interface developed by Motorola to connect controllers with peripherals. The exact introduction year and original product have not been verified. [1]

| Signal | Purpose |
| --- | --- |
| SCLK / SCK | Clock generated by the controller |
| MOSI / COPI | Controller → peripheral data |
| MISO / CIPO | Peripheral → controller data |
| CS / SS | Selects a peripheral, commonly active low |
| GND / power | Common reference and suitable peripheral supply |

The clock and data lines can be shared. Each peripheral normally uses a separate CS line; selection is not by an I2C-style bus address. A deselected peripheral must release MISO. Four-wire SPI can transmit and receive simultaneously. [2][3]

```text
ESP32 ── SCLK / MOSI / MISO ── devices A and B
      ├─ CS A ──────────────── device A
      └─ CS B ──────────────── device B
      + common GND and suitable power
```

**Electrical and topology:** SPI commonly uses push-pull signaling with one active controller and one or more peripherals. ESP32 GPIO uses 3.3 V logic; check the connected module's actual logic levels and any level shifting. CS is often active low, but verify the device. [2][3]

**Speed and distance:** SPI often runs at MHz clock rates over short board-level connections. There is no universal cable-length or maximum-speed figure: the controller, peripheral and wiring set the limits. Common uses include SD cards, displays and flash memory. An SPI peripheral in this student's kit has not yet been identified or tested. [2]

**Classic ESP32 example:** SPI3 IO_MUX pins are SCLK GPIO18, MISO GPIO19, MOSI GPIO23 and first hardware CS GPIO5; other mappings may be possible. GPIO18/19 were used in earlier coursework, so inspect current wiring before reusing them. These are reference pins, not a completed circuit. [3]

## Comparison

| Interface | Main contrast with SPI |
| --- | --- |
| I2C / I3C | Shared data/clock with addressing; I2C uses pull-ups. I3C adds features and different electrical modes. |
| RS-232 | Point-to-point serial electrical interface with different voltage levels. |
| RS-485 | Differential electrical interface for longer, multi-drop wiring; a separate protocol supplies message rules. |
| Modbus RTU | Addressed messaging protocol commonly carried over RS-485. |
| CAN | Differential bus with arbitration and error handling. |
| OneWire | Shared single data line with device identification, typically lower throughput. |

## Remarkable features and troubleshooting

- **Two directions at once:** MOSI and MISO can shift data during the same clocks; dummy data may be used when reading.
- **Selection by wire:** adding a device usually needs another CS line rather than another bus address.
- **No universal acknowledgement:** a transfer alone does not prove success; check a documented ID or status response when available. Some device-specific protocols add checks. [2]
- **Failure example:** wrong CS, clock polarity/phase, bit order, wiring or voltage can produce incorrect data. Check the datasheet, common ground and each wire; inspect SCLK, CS and data with a logic analyzer. [3][4]

## Short presentation

> SPI is a synchronous serial interface developed by Motorola. The controller shares clock and data lines with peripherals and selects each one using a chip-select pin. It can send and receive at the same time, but a transfer alone does not prove success. SPI is useful for fast, short connections such as displays and memory.
